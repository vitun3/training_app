# 12. Сценарии использования приложения (Use Cases)

## 12.1 Общая информация

Use Case описывает взаимодействие пользователя или внешней системы с приложением для достижения определённой цели.

На основании бизнес-целей и функциональных требований выделены основные сценарии использования, покрывающие ключевые возможности приложения:

* проведение и анализ тренировок;
* персонализация тренировочного процесса;
* социальное взаимодействие;
* использование спортивных устройств;
* геймификация;
* продвижение спортивных товаров и интеграция с существующими приложениями компании.

При определении набора Use Cases учитывалось, что приложение ориентировано на пользователей по всему миру, может использоваться во время поездок и тренировок в различных местах, а также должно поддерживать большое количество участников соревнований и дополнительные устройства для продвинутых спортсменов.

| Актор                                        | Описание                                                                                                                     |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Пользователь**                             | Основной пользователь приложения, выполняющий тренировки, отслеживающий результаты и взаимодействующий с другими участниками |

# 12.3 UC-01. Проведение тренировки

## Цель

Позволить пользователю провести тренировку и сохранить её результаты в приложении.

## Основной актор

**Пользователь**

## Предусловия

* пользователь авторизован;
* приложение доступно;
* пользователь может выбрать параметры тренировки.

## Основной сценарий

1. Пользователь открывает раздел тренировок.
2. Выбирает тип тренировки.
3. При необходимости выбирает тренировочный план или маршрут.
4. Запускает тренировку.
5. Приложение начинает отслеживать параметры тренировки.
6. Во время тренировки приложение получает данные от телефона и/или подключённых спортивных устройств.
7. Пользователь завершает тренировку.
8. Система сохраняет результаты.
9. Пользователь получает сводную информацию о тренировке.
10. Результат становится доступен для последующего сравнения, аналитики и персонализации.

## Альтернативные сценарии

### UC-01-A1. Нет подключения к спортивному устройству

Если внешнее устройство недоступно, приложение продолжает тренировку с использованием доступных возможностей телефона.

### UC-01-A2. Потеря соединения во время тренировки

Приложение продолжает собирать доступные данные и синхронизирует их после восстановления соединения.

## Результат

Тренировка сохранена и доступна пользователю для дальнейшего анализа.

# 12.4 UC-02. Анализ и сравнение результатов тренировки

## Цель

Предоставить пользователю возможность оценить результат тренировки и сравнить его с другими результатами.

## Основной актор

**Пользователь**

## Предусловия

* пользователь имеет сохранённую тренировку.

## Основной сценарий

1. Пользователь открывает историю тренировок.
2. Выбирает необходимую тренировку.
3. Система отображает характеристики тренировки.
4. Пользователь выбирает режим сравнения.
5. Система предоставляет сравнение:

   * с предыдущими тренировками пользователя;
   * с результатами других пользователей в регионе;
   * при наличии соответствующих данных — с результатами профессиональных спортсменов.
6. Система отображает результат сравнения.

При этом основным является сравнение пользователя с самим собой, направленное на стимулирование улучшения собственных результатов.

## Результат

Пользователь получает объективную оценку динамики своих спортивных результатов.

---

# 12.5 UC-03. Формирование и планирование тренировки

## Цель

Помочь пользователю сформировать тренировку с учётом его целей и доступного спортивного инвентаря.

## Основной актор

**Пользователь**

## Предусловия

* пользователь авторизован;
* в профиле могут быть указаны спортивные цели и инвентарь.

## Основной сценарий

1. Пользователь открывает раздел планирования тренировок.
2. Указывает желаемые параметры или цель.
3. Система анализирует доступную информацию о пользователе.
4. Система учитывает указанный спортивный инвентарь.
5. Формируется предложение по составу тренировки.
6. Пользователь корректирует предложенный вариант при необходимости.
7. Пользователь сохраняет тренировку или расписание.

Функциональность формирования тренировок и расписания, а также использование информации о спортивном инвентаре непосредственно предусмотрены исходными требованиями.

## Результат

Сформирован план тренировки и/или расписание.

---

# 12.6 UC-04. Поиск спортсменов и создание совместной группы

## Цель

Позволить пользователю найти людей со схожими спортивными интересами и организовать совместные занятия.

## Основной актор

**Пользователь**

## Предусловия

* пользователь авторизован;
* другие пользователи имеют доступные для поиска данные.

## Основной сценарий

1. Пользователь открывает поиск спортсменов.
2. Задаёт критерии поиска.
3. Система выполняет поиск пользователей:

   * со схожими интересами;
   * тренирующихся в том же месте;
   * использующих похожие маршруты;
   * тренирующихся в данный момент.
4. Система отображает подходящих пользователей.
5. Пользователь выбирает интересующих его спортсменов.
6. Пользователь создаёт или присоединяется к группе.
7. Участники получают информацию о новой группе.

Такие варианты поиска непосредственно предусмотрены исходными требованиями приложения.

## Результат

Создана или расширена спортивная группа для совместных занятий.

---

# 12.7 UC-05. Социальное взаимодействие в спортивной группе

## Цель

Обеспечить коммуникацию пользователей и формирование самоподдерживающегося спортивного сообщества.

## Основной актор

**Пользователь**

## Предусловия

* пользователь является участником спортивной группы.

## Основной сценарий

1. Пользователь открывает спортивную группу.
2. Просматривает активность участников.
3. Публикует информацию о своей тренировке или результате.
4. Другие участники получают публикацию.
5. Участники взаимодействуют с публикацией.
6. Пользователи могут обмениваться сообщениями и договариваться о совместных тренировках.

Социальные компоненты должны обеспечивать формирование групп по интересам, коммуникацию и взаимное влияние участников.

## Результат

Пользователь взаимодействует с сообществом и получает социальную мотивацию к дальнейшим тренировкам.

# 12.8 UC-06. Подключение спортивного устройства

## Цель

Подключить внешнее устройство для автоматического получения дополнительных параметров тренировки.

## Основной актор

**Пользователь**

## Внешний актор

**Спортивное устройство**

## Предусловия

* устройство поддерживается приложением;
* пользователь предоставил необходимые разрешения.

## Основной сценарий

1. Пользователь открывает настройки устройств.
2. Выбирает тип подключаемого устройства.
3. Приложение инициирует подключение.
4. Пользователь подтверждает подключение на устройстве.
5. Система проверяет соединение.
6. Устройство становится доступным для использования во время тренировок.
7. Данные устройства используются при последующих тренировках.

В качестве примеров устройств в исходном задании указаны датчики сердцебиения и кислорода.

## Альтернативные сценарии

### UC-06-A1. Устройство не поддерживается

Система сообщает пользователю о невозможности подключения.

### UC-06-A2. Пользователь не предоставил разрешение

Система запрашивает необходимые разрешения и не начинает получение данных до их предоставления.

## Результат

Спортивное устройство подключено и может передавать данные в приложение.

# 12.9 UC-07. Получение уведомления о спортивном достижении

## Цель

Повысить вовлечённость пользователя за счёт информирования его друзей и сообщества о новых достижениях.

## Основной актор

**Пользователь**

## Предусловия

* пользователь выполнил тренировку;
* система определила достижение;
* пользователь разрешил соответствующие уведомления.

## Основной сценарий

1. Пользователь завершает тренировку.
2. Система анализирует результат.
3. Определяется новое достижение или улучшение результата.
4. Система формирует уведомление.
5. Уведомление становится доступным друзьям пользователя.
6. Пользователь получает информацию о публикации.

Возможность уведомлять друзей о новых успехах является отдельным функциональным требованием.

## Результат

Спортивное достижение опубликовано или доведено до сведения выбранного круга пользователей.

# 12.10 UC-08. Участие в соревновании

## Цель

Предоставить пользователю возможность участвовать в спортивном соревновании и сравнивать свой результат с другими участниками.

## Основной актор

**Пользователь**

## Предусловия

* соревнование доступно для регистрации;
* пользователь соответствует условиям участия.

## Основной сценарий

1. Пользователь открывает список соревнований.
2. Выбирает соревнование.
3. Просматривает условия участия.
4. Регистрируется.
5. Выполняет тренировку или спортивную активность в рамках соревнования.
6. Система получает результат.
7. Результат учитывается в рейтинге.
8. Пользователь получает информацию о своём положении относительно других участников.

## Особенность

Система должна учитывать возможность проведения соревнований с большим количеством одновременно участвующих пользователей.

## Результат

Результат пользователя учтён в соревновании, а его позиция отображена в рейтинге.

# 12.11 UC-09. Получение персональных промоакций и спортивных новостей

## Цель

Повысить вовлечённость пользователя и обеспечить продвижение продукции компании посредством персонализированного контента.

## Основной актор

**Пользователь**

## Внешний актор

**Система промоакций**

## Основной сценарий

1. Пользователь выполняет тренировки.
2. Система анализирует характер его спортивной активности.
3. Определяется релевантный контент.
4. Система получает доступные промоакции и новости.
5. При наличии региональных ограничений учитывается регион пользователя.
6. Пользователь получает соответствующее предложение или новость.

Исходные требования предусматривают внедрение промоакций и спортивных новостей в зависимости от характера тренировок, а также региональные промоакции.

## Результат

Пользователь получает релевантный контент и предложения.

# 12.12 UC-10. Переход к покупке спортивного товара

## Цель

Обеспечить бесшовное использование существующей торговой экосистемы компании для поддержки продаж.

## Основной актор

**Пользователь**

## Внешний актор

**Существующее приложение компании**

## Предусловия

* пользователю показан релевантный товар или предложение;
* существующее приложение компании доступно.

## Основной сценарий

1. Пользователь получает рекомендацию спортивного товара.
2. Открывает карточку предложения.
3. Выбирает товар.
4. Приложение передаёт пользователя в существующее приложение компании.
5. Пользователь продолжает процесс покупки в существующей системе.

Требование предусматривает лёгкую интеграцию существующих приложений компании для облегчения продаж.

## Результат

Пользователь переходит из спортивного приложения в существующий канал покупки.
