# 14.3 Представление многозадачности (Concurrency)

## 14.3.1 Назначение

Представление многозадачности описывает параллельное выполнение операций и взаимодействие независимых компонентов.

Для системы особенно важны:

- параллельная обработка тренировок;
- одновременная обработка телеметрии;
- массовые соревнования;
- асинхронная обработка событий;
- независимая обработка рекомендаций и аналитики.

---

## 14.3.2 Параллельная обработка тренировки

После завершения тренировки несколько компонентов могут независимо обработать одно событие:

```text
                  WorkoutCompleted
                         │
                      Event Bus
                         │
        ┌────────────────┼────────────────┐
        │                │                │
        ▼                ▼                ▼
   Analytics       Competition      Recommendation
        │                │                │
        ▼                ▼                ▼
  Анализ данных     Рейтинг       Новая рекомендация
                         │
                         │
                         ▼
                    Notification
```

Эти операции не должны выполняться последовательно.

---

## 14.3.3 Обработка телеметрии

Телеметрия может поступать одновременно от большого количества пользователей и устройств.

Поэтому:

- данные принимаются асинхронно;
- сообщения распределяются между обработчиками;
- обработчики могут масштабироваться горизонтально;
- обработка одного пользователя не должна блокировать обработку другого.

Упрощённая модель:

```text
Device 1 ──┐
Device 2 ──┤
Device 3 ──┤
Device N ──┘
       │
       ▼
  Event Bus
       │
 ┌─────┼─────┐
 ▼     ▼     ▼
W1    W2    W3
 │     │     │
 └─────┼─────┘
       ▼
Workout Service
```

---

## 14.3.4 Идемпотентность

Поскольку сообщения могут быть доставлены повторно, обработчики событий должны быть идемпотентными.

Например, повторная доставка:

```text
WorkoutCompleted #123
       │
       ├──► Processing #1 ──► SUCCESS
       │
       └──► Processing #2 ──► already processed
```

Повторная обработка не должна приводить к:

- двойному начислению достижения;
- двойному учёту результата соревнования;
- повторному списанию ресурсов;
- созданию нескольких одинаковых уведомлений.

---

## 14.3.5 Пиковая нагрузка во время соревнований

Во время массового соревнования нагрузка может резко возрастать.

Архитектура должна обеспечивать:

- увеличение количества экземпляров сервисов;
- распределение сообщений между обработчиками;
- независимое масштабирование сервиса соревнований;
- возможность временного увеличения пропускной способности Event Bus.

При этом увеличение нагрузки на соревнования не должно приводить к остановке тренировок или социальных функций.
