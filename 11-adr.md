# ADR-001. Выбор архитектурного стиля системы
## Рассмотренные альтернативы

В процессе проектирования были рассмотрены следующие варианты:

1. Монолитная архитектура.
2. Сервис-ориентированная архитектура (SOA).
3. Микросервисная архитектура.
4. Событийно-ориентированная микросервисная архитектура (Event-Driven Microservices).

Сравнительный анализ альтернатив представлен в разделе **«Анализ архитектурных опций»** настоящего документа.

---

## Принятое решение

В качестве архитектурного стиля выбрана **событийно-ориентированная микросервисная архитектура (Event-Driven Microservices)**.

Основные принципы реализации:

- разделение системы на независимые бизнес-домены;
- отдельный сервис для каждой функциональной области;
- собственное хранилище данных каждого сервиса;
- отсутствие прямого доступа к данным других сервисов;
- преимущественно асинхронное взаимодействие посредством обмена событиями;
- использование синхронного взаимодействия только в сценариях, требующих немедленного ответа пользователю;
- возможность независимого масштабирования и развертывания каждого сервиса.

Принятое решение обеспечивает:

- независимое развитие команд разработки;
- возможность постепенного расширения платформы;
- независимое масштабирование сервисов;
- уменьшение влияния отказов отдельных компонентов;
- эффективную обработку потоковых данных;
- упрощение интеграции новых внешних сервисов и устройств.
